## 1. Executive Summary & Security Posture

ColdRescue implements defense-in-depth access controls across foundational infrastructure, streaming consumers, Step Functions orchestration, and API entry points. In accordance with the project constraints and AWS best practices:
1. **Zero wildcard identities:** No broad `AdministratorAccess` or wildcard service principals are provisioned.
2. **Resource-scoped ARNs:** All DynamoDB, Amazon Location Service, S3, SQS, and SageMaker permissions are explicitly bound to environment-qualified resource ARNs.
3. **Condition-scoped CloudWatch Metrics:** Where AWS CloudWatch requires `resources: ["*"]` for `cloudwatch:PutMetricData`, strict IAM `StringEquals` conditions limit metric emission solely to designated project namespaces.
4. **Separation of Duties:** State machine orchestrators, telemetry consumers, stream listeners, and API Gateways operate under distinct, minimally scoped IAM roles.

## 3. Justification of Required Wildcard Actions

> [!IMPORTANT]
> **AWS IAM Architectural Scoping Limitations:**
> AWS IAM does **not** support resource-level scoping (resource ARNs) for `cloudwatch:PutMetricData` or AWS X-Ray write actions (`xray:PutTraceSegments`, `xray:PutTelemetryRecords`). Specifying an ARN for these actions results in an authorization failure. To achieve strict least privilege without resource ARNs:
> - `cloudwatch:PutMetricData` actions are rigidly constrained using IAM policy `Condition` blocks (`StringEquals: cloudwatch:namespace = <designated namespace>`).
> - `xray:PutTraceSegments` and `xray:PutTelemetryRecords` are restricted to the active Lambda tracing runtime managed identity without any broader wildcard permissions (e.g. zero `xray:*` administration privileges).

| Action | Specified Resource | Condition / Scope Restriction | Justification |
| :--- | :--- | :--- | :--- |
| `cloudwatch:PutMetricData` | `*` | `StringEquals: cloudwatch:namespace = "ColdRescue/Thermal"` | CloudWatch does not support resource-level ARNs for custom metric publishing. Namespace scoping guarantees that the Lambda can never tamper with or emit metrics into any other AWS or project namespace. |
| `cloudwatch:PutMetricData` | `*` | `StringEquals: cloudwatch:namespace = "ColdRescue/Events"` | CloudWatch does not support resource-level ARNs. Applied strictly to DynamoDB Streams consumer to record `EventsPersistedCount` restricted to the `ColdRescue/Events` namespace. |
| `cloudwatch:PutMetricData` | `*` | `StringEquals: cloudwatch:namespace = "ColdRescue/Policy"` | CloudWatch does not support resource-level ARNs. Scoped strictly to `ColdRescue/Policy` namespace to record `PolicyPassedCount` and `PolicyBlockedCount`. |
| `xray:PutTraceSegments`, `xray:PutTelemetryRecords` | `*` | Native AWS CDK X-Ray Managed Policy | AWS X-Ray daemon and active tracing SDK require publishing trace segments across ephemeral trace IDs, which do not have static ARNs and do not support resource-level scoping in IAM. |

## 4. Remediation and Verification Summary

1. **Tag Consistency:** Standardized all resource tags to lowercase `project: coldrescue` across all stacks to avoid IAM case-collision anomalies.
2. **No Orphaned Privileges:** No `iam:*` administration permissions or cross-service wildcard rights exist in any stack template.
3. **Idempotency Guarantees:** All IAM write policies on DynamoDB and SQS align with idempotent operation keys (`idempotency_key` partition queries and deduplication buffers).
